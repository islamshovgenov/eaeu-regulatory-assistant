# Ограничения системы

Документ намеренно написан жёстко: в предметной области лекарственного
регулирования честное «не знаю» полезнее правдоподобного вывода.

## 1. Главное ограничение

**Система не является источником нормативных требований и не заменяет
регуляторного эксперта.** Она ищет фрагменты официальных документов и
формулирует предварительную гипотезу со ссылками. Итоговое решение о программе
исследований принимает уполномоченный специалист.

## 2. Ограничения нормативной базы

| Ограничение | Влияние на ответ |
|---|---|
| Действующая редакция акта не устанавливается автоматически | `version_status = requires_expert_validation`; в ответе появляется соответствующее ограничение |
| Консолидированные редакции не формируются | акт и акты о внесении изменений индексируются раздельно; формулировка может относиться к исходной редакции |
| Статус «действует / утратил силу» берётся только из явных маркеров источника | у большинства документов статус `unknown` |
| Даты вступления в силу и окончания действия обычно не публикуются машиночитаемо | поля `effective_date` / `expiration_date` часто пусты |
| Отсканированные PDF (значительная часть рекомендаций Экспертного комитета) | индексируется только карточка документа, текст не доступен поиску |
| Форматы `.doc` и `.rtf` не поддерживаются парсером | документы остаются в реестре, но не в индексе |
| Часть страниц источника периодически отвечает 404/500 | отдельные акты могут отсутствовать в корпусе |
| На отдельных страницах Коллегии файл `<stem>_doc.pdf` — англоязычный перевод, а русский текст лежит в файле с другим именем | такие документы отсеиваются языковым фильтром и не попадают в индекс — см. раздел 3.1 |

### 2.1 Известный пробел покрытия: русские версии части руководств Коллегии

Правило отбора файлов предпочитает PDF, потому что на `docs.eaeunion.org`
русский текст акта обычно публикуется именно как `<stem>_doc.pdf`, тогда как
`<stem>_doc.docx` содержит версию на другом национальном языке. Но на части
страниц Коллегии соглашение иное: `_doc.pdf` там — **английский перевод**.
Проверка языка по содержимому корректно исключает такой файл из индекса, однако
русская версия при этом не подхватывается, так как имеет другое имя файла.

Затронуты, в частности:

* Решение Коллегии № 113 — Руководство по валидации аналитических методик;
* Решение Коллегии № 151 — Руководство по нормативному документу по качеству.

Практическое следствие: в метриках поиска категории `quality` (0/4) и
`nonclinical` (1/6) заметно слабее остальных. Ядро предметной области —
регистрация, биоэквивалентность, биовейвер, выбор референтного препарата,
биологические препараты — покрыто полностью (7/7, 6/6, 4/4, 2/2, 3/3).

**Как устранить.** В `ingestion/discover_sources.py` заменить выбор одного файла
на стем (`_select_preferred_files`) на сохранение всех форматов, а выбор русской
версии полностью передать проверке содержимого
(`ingestion.normalizer.is_russian_text`) на этапе парсинга, добавив дедупликацию
документов, у которых совпадают тип, номер и дата принятия. После этого:

```
python -m ingestion.discover_sources
python -m ingestion.downloader
python scripts/rebuild_index.py --rechunk
```

Ориентировочно 15 минут докачки и около 45 минут векторизации на CPU.

## 3. Ограничения поиска

* Извлечение структуры основано на типовой разметке актов ЕЭК. Нестандартно
  оформленный документ может дать менее точные координаты (раздел/пункт).
* Для PDF границы абзацев восстанавливаются эвристически, поэтому номера
  страниц надёжнее, чем номера пунктов.
* Реранкер по умолчанию — лексический. Кросс-энкодер точнее, но требует ~2.2 ГБ
  и включается вручную.
* Поиск по МНН опирается на словарь, извлечённый из заголовков рекомендаций
  Экспертного комитета, и на курируемую таблицу синонимов. Вещество, не
  встречающееся в корпусе, не будет распознано как МНН.

## 4. Ограничения генерации

* Качество формулировок зависит от выбранной LLM. Провайдер и модель
  указываются в интерфейсе рядом с каждым ответом.
* Модель может неверно применить корректно найденную норму. Валидация проверяет
  наличие и достоверность ссылок, но **не проверяет корректность юридического
  толкования**.
* Утверждения без ссылки автоматически понижаются до интерпретации, однако
  интерпретация тоже может быть ошибочной.
* Уровень уверенности отражает качество обоснования (наличие обязательных
  источников, доля утверждений со ссылками, статус редакции), а **не**
  вероятность того, что регулятор согласится с выводом.

## 5. Ограничения оценки качества

* Набор `data/eval/questions.csv` размечен автоматически: у всех вопросов
  `needs_expert_validation = true`. Это **не** ground truth.
* Метрики Recall@k и MRR измеряют, находит ли поиск ожидаемый документ, а не
  правильность регуляторного вывода.
* LLM-as-a-judge не используется как единственный критерий качества; для
  содержательной оценки необходима экспертная валидация.
* Демонстрационные кейсы в `data/eval/cases/cases.json` проверяют **поведение**
  системы (задаёт ли уточняющие вопросы, отказывается ли при отсутствии
  оснований), а не совпадение с эталонным заключением.

## 6. Ограничения предметной области

* Охвачены лекарственные средства для медицинского применения в рамках ЕАЭС.
  Медицинские изделия, ветеринарные препараты, БАД и национальные процедуры
  государств-членов вне охвата.
* Система не даёт медицинских рекомендаций и отклоняет такие запросы.
* Международные источники (ICH/EMA/WHO) включены как справочные и никогда не
  выдаются как обязательные требования ЕАЭС.

## 7. Технические ограничения

* Локальный режим Qdrant рассчитан на один процесс. Для параллельной работы
  используйте `QDRANT_MODE=server` (`docker compose up -d qdrant`).
* BM25-индекс держится в памяти целиком; на корпусе в сотни тысяч чанков
  потребуется перейти на полнотекстовый поиск СУБД или на serverless-решение.
* Индексация на CPU занимает существенное время; при смене embedding-модели
  требуется полная пересборка индекса.
* Файл BM25-индекса сохраняется через `pickle`. Загружайте только индекс,
  собранный вами: `pickle` не предназначен для недоверенных данных.

## 8. Что считается корректным поведением

* «Достаточное нормативное основание в доступной базе знаний не найдено» —
  правильный ответ, а не сбой.
* Уточняющие вопросы вместо категорического вывода при неполных данных о
  препарате — правильное поведение.
* Явное указание на расхождение между источниками вместо выбора «правильного»
  — правильное поведение.
