# Дизайн RAG-системы

## 1. Почему RAG, а не fine-tuning

Нормативная база ЕАЭС меняется постоянно: только к Решению Совета ЕЭК № 78
опубликовано более десятка актов о внесении изменений. Дообученная модель
«запоминает» состояние на момент обучения, не может показать источник и не
позволяет отличить действующую норму от отменённой. RAG решает все три задачи:
корпус обновляется скриптом, каждое утверждение сопровождается ссылкой на
конкретный фрагмент, а версия документа хранится как метаданные.

Fine-tuning в проекте не используется. Модель не обучается на нормативных
документах.

## 2. Structure-aware chunking

### 2.1 Проблема наивного чанкинга

Деление текста «каждые N символов» разрывает пункт посередине и теряет
родительский контекст. Фрагмент «…допускается при выполнении условий,
установленных настоящим разделом» бесполезен без указания, о каком разделе и
каком приложении идёт речь, и его нельзя процитировать.

### 2.2 Реализация

`ingestion/structure_parser.py` распознаёт разметку актов ЕЭК регулярными
выражениями, каждое из которых прокомментировано в коде:

| Уровень | Пример в тексте | Поле метаданных |
|---|---|---|
| Приложение | `ПРИЛОЖЕНИЕ № 2` | `appendix` |
| Часть | `ЧАСТЬ II` | `part` |
| Раздел | `III. Требования к…` / `РАЗДЕЛ III` | `section` |
| Глава | `Глава 2. Наименование` | `chapter` |
| Подраздел | ненумерованный заголовок | `subsection` |
| Пункт | `42. Освобождение…` | `paragraph` |
| Подпункт | `а) …`, `1) …` | `subparagraph` |
| Таблица | извлечённая таблица DOCX | `is_table` |

Парсер работает как конечный автомат: при встрече заголовка он обновляет
состояние и сбрасывает вложенные уровни, а каждый абзац получает снимок
текущего состояния. Продолжения абзацев, разорванные разрывом страницы,
склеиваются функцией `merge_continuations`.

### 2.3 Правила формирования чанка

1. Чанк **никогда не пересекает** границу приложения, части, раздела или главы
   (`StructuralUnit.context_key`).
2. Пункт — атомарная единица; он делится только если сам превышает
   `CHUNK_MAX_CHARS`, и тогда по границам предложений с перекрытием.
3. К телу чанка добавляется префикс с путём заголовков
   (`[Решение Совета ЕЭК № 85 … / Приложение № 1 · Раздел III · п. 42]`), чтобы
   эмбеддинг «видел» контекст.
4. Одинокий заголовок без нормативного содержания не индексируется.
5. `chunk_id` детерминирован: `document_id + координаты + порядковый номер +
   хеш нормализованного текста`. Повторный запуск даёт те же идентификаторы —
   ссылки остаются валидными между пересборками индекса.

## 3. Эмбеддинги

### 3.1 Выбор модели

По умолчанию — **`intfloat/multilingual-e5-base`**.

Обоснование:

* обучена на 100+ языках, включая русский, и стабильно показывает высокое
  качество на многоязычном semantic search (MTEB / MIRACL);
* асимметричные префиксы `query:` / `passage:` соответствуют задаче: короткий
  вопрос ищется по длинным нормативным абзацам;
* 768 измерений и ~280 МБ — запускается на CPU ноутбука без GPU и без
  оплаты API, что было прямым требованием к проекту;
* лицензия MIT, модель скачивается один раз и далее работает офлайн.

Альтернативы и почему не они: `multilingual-e5-large` (1024d, ~2.2 ГБ) даёт
небольшой прирост качества ценой заметного замедления индексации на CPU;
`paraphrase-multilingual-MiniLM-L12-v2` быстрее, но заметно слабее на длинных
юридических текстах; `text-embedding-3-large` требует оплаты API и не может
быть режимом по умолчанию.

Модель меняется одной переменной окружения `EMBEDDING_MODEL` с последующим
`python scripts/rebuild_index.py`.

### 3.2 Провайдеры

`EMBEDDING_PROVIDER=local` — sentence-transformers (по умолчанию);
`EMBEDDING_PROVIDER=openai` — `text-embedding-3-large`.
Интерфейс `EmbeddingProvider` (`ingestion/embeddings.py`) позволяет добавить
новый бэкенд одним классом.

## 4. Гибридный поиск

### 4.1 Зачем оба метода

| Тип запроса | Кто справляется |
|---|---|
| «когда можно не проводить исследование сравнительной биодоступности» | вектор (перефразировка → «биовейвер») |
| «пункт 42», «AUC(0-t)», «90% доверительный интервал» | BM25 (точные токены) |
| «высоковариабельный», «референтный препарат» | оба, но BM25 надёжнее в терминологии |

### 4.2 Токенизация BM25

`ingestion/indexer.tokenize` приводит текст к нижнему регистру, заменяет `ё→е`,
извлекает токены `[а-яa-z]+` и числа (`90`, `0`, `42`), удаляет русские
служебные слова. Благодаря этому `AUC(0-t)` превращается в `auc`, `0`, `t`, а
не теряется целиком.

### 4.3 Fusion

Reciprocal Rank Fusion:

```
score(d) = w_vec / (k + rank_vec(d)) + w_bm25 / (k + rank_bm25(d))
```

`k = RRF_K` (по умолчанию 60). RRF выбран потому, что не требует калибровки
между косинусной близостью (0..1) и оценкой BM25 (неограниченная) и устойчив к
выбросам. Фрагмент, найденный обоими методами, поднимается выше, чем фрагмент,
занявший первое место только у одного из них.

Настраиваемые параметры: `VECTOR_TOP_K`, `BM25_TOP_K`, `FINAL_TOP_K`, `RRF_K`,
`RRF_VECTOR_WEIGHT`, `RRF_BM25_WEIGHT`.

### 4.4 Мульти-запрос

Один вопрос превращается в несколько формулировок
(`app/rag/retriever.build_profile_queries`): базовое описание препарата,
тематические запросы (регистрация / биоэквивалентность / биовейвер /
референтный препарат / дополнительные дозировки / высокая вариабельность / узкий
терапевтический диапазон / модифицированное высвобождение) и МНН-специфичные
запросы. Результаты каждой формулировки объединяются вторым уровнем RRF.

### 4.5 Поиск по МНН

`app/regulatory/inn.py` строит варианты написания: исходная форма,
транслитерация в обе стороны, курируемые синонимы (`парацетамол` ↔
`acetaminophen`), усечённые основы для русских падежей. Словарь МНН **строится
из корпуса**: заголовки рекомендаций Экспертного комитета содержат МНН в
кавычках-ёлочках («эстриол»), их извлекает `extract_inns_from_title`, результат
сохраняется в `data/processed/inn_vocabulary.json`.

## 5. Реранкинг

После слияния кандидаты переранжируются:

* по умолчанию — `LexicalOverlapReranker`: доля редких токенов запроса,
  присутствующих в чанке, плюс бонус за то, что фрагмент является нумерованным
  пунктом, минус штраф за слишком короткий фрагмент; результат смешивается с
  оценкой RRF. Не требует загрузок и работает мгновенно;
* при `RERANK_ENABLED=true` — кросс-энкодер `BAAI/bge-reranker-v2-m3`. Он
  заметно точнее, но весит ~2.2 ГБ и на CPU добавляет секунды к каждому
  запросу, поэтому выключен по умолчанию. Любая ошибка загрузки модели
  приводит к тихому откату на лексический реранкер.

## 6. Политика уровней источников

```
TIER_1  обязательный акт ЕАЭС/ЕЭК (решения Совета и Коллегии)
TIER_2  руководство/рекомендация Коллегии ЕЭК
TIER_3  рекомендация Экспертного комитета ЕЭК (в т.ч. по конкретному МНН)
TIER_4  ICH / EMA / WHO — только справочно
TIER_5  научная литература — только для научных сведений
```

`RegulatoryRetriever._apply_tier_policy`:

* доля TIER-4 в финальном контексте ограничена 25 % — международные
  руководства не могут вытеснить обязательные требования;
* если в отобранном контексте не оказалось ни одного TIER-1/TIER-2 фрагмента,
  лучшие обязательные кандидаты добавляются принудительно;
* при `SUPPLEMENTARY_SOURCES_ENABLED=false` TIER-4 исключается полностью.

На уровне валидации утверждение, опирающееся только на TIER-4, не может быть
нормативным требованием.

## 7. Контекст для модели

`CitationRegistry.context_block()` формирует блок, где каждый фрагмент:

```
<<<ФРАГМЕНТ 3 НАЧАЛО>>>
[3] Решение Совета ЕЭК № 85 от 03.11.2016 · Приложение № 1 · Раздел III · п. 42
    источник: EAEU | Обязательный нормативный акт ЕАЭС
    статус: статус не подтверждён автоматически | первоначальная редакция; известны акты о внесении изменений
    текст:
    …
<<<ФРАГМЕНТ 3 КОНЕЦ>>>
```

Модель видит не только текст, но и уровень источника и статус редакции — этого
достаточно, чтобы корректно оговорить ограничения в ответе.

## 8. Structured output

Модель возвращает JSON, валидируемый Pydantic-схемой `RegulatoryAssessment`
(или `ChatAnswer` в режиме чата). Ответ модели проходит толерантную нормализацию
(`_coerce_assessment`): неизвестные значения перечислений заменяются
безопасными (`insufficient_data`, `clinical`), нечисловые `citation_ids`
отбрасываются. Затем — строгая валидация обоснованности
(`app/regulatory/validators.py`).

## 9. Что система принципиально не делает

* не формирует консолидированные редакции документов;
* не считает более новый документ автоматически отменяющим более старый;
* не выдаёт TIER-4 за требования ЕАЭС;
* не создаёт цитаты — только ссылается на заранее пронумерованные фрагменты;
* не отвечает по памяти модели при пустом результате поиска.
