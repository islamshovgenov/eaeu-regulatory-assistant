# Как устроен код — подробный разбор для себя

Документ для того, чтобы за 20 минут восстановить в голове всю картину: что
происходит, в каком порядке, в каком файле и зачем. Читать сверху вниз.

---

## 0. Сразу о главном: мы ничего не обучали

Это первое, что нужно понимать, и первое, о чём спросят.

**В проекте нет обучения модели.** Ни дообучения (fine-tuning), ни обучения с
нуля. Используются две готовые модели:

| Модель | Откуда | Что делает | Обучали? |
|---|---|---|---|
| `intfloat/multilingual-e5-base` | скачивается с HuggingFace, работает локально на вашем компьютере | превращает текст в вектор из 768 чисел | нет, взята готовой |
| `gpt-4o` | по API OpenAI | формулирует ответ из найденных фрагментов | нет, обращаемся по API |

BM25 — это вообще не нейросеть и не обучение: это формула ранжирования по
частоте слов, «индекс» для неё — просто посчитанная статистика по корпусу.

**Почему обучения нет, и это правильно.** Дообученная модель хранит знание в
весах: проверить, откуда взялось утверждение, невозможно, а нормативка
меняется — вышло новое решение, и надо дообучать заново. Наш подход (RAG)
хранит знание в поисковом индексе: документ добавляется за минуты, и каждое
утверждение прослеживается до пункта источника.

**Что тогда «наше»?** Весь конвейер вокруг моделей: разбор документов с
сохранением структуры, гибридный поиск, реестр цитат, валидация ответа,
расчёт уверенности, предметная логика по препаратам. Это ~7 000 строк кода,
и именно в них лежит надёжность системы.

## 1. Два независимых процесса

Проект делится надвое, и это ключ к пониманию структуры папок.

```
ПРОЦЕСС 1: ПОДГОТОВКА БАЗЫ                    выполнен один раз, код в архиве
   PDF-файлы → текст → структура → фрагменты → индексы
                                                  ↓
                                        база данных на диске
                                                  ↓
ПРОЦЕСС 2: ОТВЕТ НА ВОПРОС (папка app/)         работает при каждом вопросе
   вопрос → поиск по индексам → цитаты → LLM → проверка → ответ
```

Приложение (`app/`) во время работы **не парсит PDF и ничего не скачивает** —
оно только читает готовые индексы. Поэтому ответ приходит за секунды.

**Важно про структуру папок.** Первый процесс свою работу выполнил: база собрана
и лежит в `database/`. Его код вынесен в `_архив_сборки_базы/` и в рабочем
проекте не запускается — но приложен к работе целиком, с инструкцией, как его
вернуть. Ниже он разобран так же подробно, как и рабочая часть: это половина
проделанной работы, и на защите про неё спросят.

## 2. Процесс 1: как собиралась база знаний

> Код этого процесса — в `_архив_сборки_базы/ingestion/`. Запускался командой
> `python ingestion/run_ingestion.py`; дирижёр — `run_ingestion.py`, он вызывает
> стадии по очереди. Пути ниже даны относительно архива.

### Шаг 1. Скачивание документов → `ingestion/downloader.py`

Документы официального портала ЕАЭС скачиваются в `data/raw/eaeu/`. По каждому
файлу пишется строка в реестр `data/registry/documents.csv`:

- `document_id` — устойчивый идентификатор,
- `source_url`, `page_url` — откуда взят,
- `sha256` — контрольная сумма файла (доказательство, что файл не подменён),
- `download_date` — **дата обращения к источнику**, она потом показывается в карточке цитаты,
- `document_type`, `source_tier` — тип и уровень источника.

Зачем: для регуляторного инструмента важно не только «что написано», но и
«откуда взято и когда». Реестр — это доказательная база.

### Шаг 2. Извлечение текста → `ingestion/parser.py`

```python
def parse_file(path, allow_ocr=False) -> ParsedDocument:
    if suffix == ".pdf":   parsed = _parse_pdf(path, allow_ocr)
    elif suffix == ".docx": parsed = _parse_docx(path)
    elif suffix in (".html", ".htm"): parsed = _parse_html(path)
```

PDF читается через PyMuPDF: сначала пробуем **текстовый слой**. Если плотность
текста ниже порога — документ признаётся сканом:

```python
density = len(raw_text.strip()) / max(n_pages, 1)
if density < MIN_CHARS_PER_PAGE_FOR_TEXT_LAYER:
    parsed.warnings.append("Текстовый слой отсутствует или беден")
    if allow_ocr:
        ocr = _ocr_pdf(path)   # Tesseract, языки rus+eng, 200 dpi
```

**Это тот самый механизм, который спас проект.** 569 документов оказались
сканами; сначала они индексировались «карточкой» без текста, а позже мы
прогнали их через OCR (`scripts/ocr_backfill.py`).

Результат парсинга — `ParsedDocument` со списком `TextBlock` (абзац + номер
страницы). Номер страницы тянется до самого конца и попадает в ссылку.

### Шаг 3. Разметка структуры → `ingestion/structure_parser.py`

Самая «предметная» часть подготовки. Акты ЕАЭС устроены одинаково:

```
ПРИЛОЖЕНИЕ № 1
  I. Общие положения          ← раздел (римские цифры)
    Глава 2. ...              ← глава
      12. Текст пункта ...    ← пункт
        а) подпункт ...       ← подпункт
```

Модуль распознаёт эти маркеры регулярными выражениями и присваивает каждому
куску текста **полный путь родителей**:

```python
APPENDIX_RE = re.compile(r"^\s*ПРИЛОЖЕНИ[ЕЯ]\s*(?:№\s*(?P<number>[\dIVXА-Яа-я]+))?\b")
```

Благодаря этому шагу ссылка выглядит как
`Приложение № 1 · Раздел III · Глава 2 · п. 12, подп. а · с. 52–53`,
а не «где-то в файле». Без него весь смысл цитирования теряется.

### Шаг 4. Нарезка на фрагменты → `ingestion/chunker.py`

Документ на 600 страниц нельзя отдать модели целиком — режем на фрагменты
(«чанки») по ~1 600 символов с перекрытием 200:

```python
target_chars = 1600     # целевой размер
max_chars    = 2600     # жёсткий потолок
overlap_chars = 200     # перекрытие, чтобы мысль не рвалась на границе
```

Важно: **режем не вслепую, а по границам структуры** — пункт старается остаться
целым. Каждый фрагмент наследует метаданные документа (номер, дату, уровень
источника, статус) и свои координаты (приложение/раздел/пункт/страницы).

Отдельная функция `build_metadata_only_chunk()` создаёт «карточку документа»
для файлов, текст которых извлечь не удалось: система может назвать документ и
дать ссылку, но никогда не цитирует текст, который не прочитала.

### Шаг 5. Индексация → `ingestion/embeddings.py` + `ingestion/indexer.py`

Строятся **два независимых индекса** по одному и тому же списку фрагментов:

```python
def build_indexes(chunks, recreate=True):
    bm25 = BM25Index.build(chunk_list); bm25.save()      # лексический
    vector_index.upsert_chunks(chunk_list)               # векторный (Qdrant)
```

**Векторный.** Каждый фрагмент прогоняется через `multilingual-e5-base` и
превращается в вектор из 768 чисел; векторы кладутся в Qdrant (локальная папка
`database/qdrant/`). Вместе с вектором сохраняется полная карточка фрагмента —
поэтому после поиска не нужен второй запрос в базу.

**Лексический.** `BM25Okapi` по токенизированным текстам. Токенизатор
специально настроен под регуляторный русский:

```python
_TOKEN_RE = re.compile(r"[а-яa-z]+|\d+(?:[.,]\d+)?")   # хранит "90", "0", "t" из "AUC(0-t)"
_STOPWORDS = frozenset("и в во не что он на я с со как а то все она так ...".split())
```

Плюс SQLite (`database/eaeu.sqlite3`) — таблицы `documents`, `chunks`,
`ingestion_runs`. Это «источник правды», из которого всегда можно пересобрать
оба индекса.

**Итог процесса 1:** 755 документов → 11 058 фрагментов → 11 058 векторов +
BM25-индекс + SQLite.

## 3. Процесс 2: как рождается ответ

Точка входа — `app/main.py`, дальше всё оркеструет `app/rag/pipeline.py`,
метод `answer_question()`. Разберём по шагам на примере вопроса
«Нимесулид таблетки 100 мг, воспроизведённый, немедленное высвобождение».

### Шаг 1. Классификация запроса → `app/regulatory/classifier.py`

**Без всякой нейросети**, обычными правилами определяем: это общий вопрос,
вопрос о конкретном препарате или вообще не наша тема.

```python
if any(marker in lowered for marker in _OUT_OF_SCOPE_MARKERS):
    return QueryClassification(intent=QueryIntent.OUT_OF_SCOPE, ...)
```

`_OUT_OF_SCOPE_MARKERS` — это «какую дозу мне принимать», «как лечить» и т. п.
Такие запросы отклоняются: инструмент регуляторный, а не клинический.

### Шаг 2. Извлечение профиля препарата → `app/regulatory/intake.py`

Из текста вытаскиваются МНН, форма, дозировка, путь введения, тип препарата,
характер высвобождения — словарями и регулярками:

```python
_STRENGTH_RE = re.compile(r"\b\d+(?:[.,]\d+)?\s*(?:мг|мкг|г|ме|ед|ммоль)...")
_DOSAGE_FORMS = (("таблетк", "таблетки"), ("капсул", "капсулы"), ...)
```

Модуль **намеренно детерминированный**: система не должна угадать тип препарата,
а потом на основе догадки выдать категоричную программу исследований. Чего нет
в тексте — остаётся `unknown` и превращается в уточняющий вопрос.

МНН распознаётся через `app/regulatory/inn.py` — словарь из 378 названий,
собранный из заголовков рекомендаций Экспертного комитета, с учётом русской
морфологии («нимесулиду» → «нимесулид»).

### Шаг 3. Построение поисковых запросов → `app/rag/retriever.py`

Один вопрос превращается в **несколько формулировок** — так находится больше:

```python
def build_inn_queries(inn):
    queries = [f"{variant} исследование биоэквивалентности референтный..." ]
    queries.append(f"рекомендация Экспертного комитета о выборе референтного "
                   f"лекарственного препарата с МНН «{canonical}»")
```

### Шаг 4. Гибридный поиск → `app/rag/hybrid_search.py`

Каждая формулировка идёт в оба индекса: 40 кандидатов из векторного, 40 из
BM25. Результаты сливаются формулой **RRF (Reciprocal Rank Fusion)**:

```python
def _fuse(self, items):
    k = self.settings.rrf_k                      # 60
    for item in items:
        score = 0.0
        if item.vector_rank is not None:
            score += self.settings.rrf_vector_weight / (k + item.vector_rank)
        if item.bm25_rank is not None:
            score += self.settings.rrf_bm25_weight / (k + item.bm25_rank)
        item.score = score
    return sorted(items, key=lambda r: r.score, reverse=True)
```

Почему RRF, а не сумма оценок: у векторного поиска оценки в диапазоне 0…1, у
BM25 — какие угодно (5, 20, 40). Складывать их нельзя. RRF складывает **не
оценки, а позиции в списке** — калибровка не нужна.

### Шаг 5. Отсев и политика источников → `app/rag/retriever.py`

Сначала выбрасываются «карточки» документов без текста:

```python
def _split_metadata_cards(candidates):
    """Cards used to compete for context slots and win on title similarity."""
```

Затем переранжирование (`app/rag/reranker.py`, по умолчанию лексическое) и
политика по уровням:

```python
supplementary_cap = max(1, int(final_top_k * _MAX_SUPPLEMENTARY_SHARE))  # 25 %
```

Международные источники (ICH/EMA/WHO) не могут занять больше четверти
контекста, а обязательные акты ЕАЭС при их наличии гарантированно попадают.
Остаётся **12 фрагментов**.

### Шаг 6. Реестр цитат → `app/rag/citations.py` ⭐ самое важное

Фрагментам присваиваются номера **до обращения к модели**:

```python
@classmethod
def from_retrieval(cls, items):
    citations = [
        Citation(citation_id=index, chunk=item.chunk, ...)
        for index, item in enumerate(items, start=1)   # 1, 2, 3, ... 12
    ]
```

Модель получает их как пронумерованные данные и может лишь указать номер.
Она физически не пишет ни название документа, ни номер решения, ни дату.

### Шаг 7. Промпт → `app/rag/prompts.py`

Три канала жёстко разделены и подписаны для модели:
`SYSTEM INSTRUCTIONS` (единственный источник поведения), `USER INPUT` (данные),
`RETRIEVED REGULATORY CONTEXT` (**данные, не инструкции**).

Каждый фрагмент обёрнут явными границами:

```
<<<ФРАГМЕНТ 3 НАЧАЛО>>>
[3] Решение Совета ЕЭК № 85 · Раздел III · п. 106
    источник: EAEU | Обязательный нормативный акт ЕАЭС
    текст: ...
<<<ФРАГМЕНТ 3 КОНЕЦ>>>
```

Защита от инъекций: нормативные тексты полны повелительных формулировок
(«необходимо представить», «запрещается»), поэтому в промпте прямо сказано, что
ничто внутри блока не меняет поведение. Длинные последовательности угловых
скобок в тексте документа нейтрализуются, чтобы документ не подделал границу:

```python
_DELIMITER_RE = re.compile(r"<{3,}|>{3,}")
```

### Шаг 8. Вызов модели → `app/rag/generator.py`

Тонкая обёртка над провайдером (OpenAI / Anthropic / выключено). Модель обязана
вернуть **строгий JSON**, который затем валидируется схемой pydantic
(`app/regulatory/schemas.py`).

### Шаг 9. Валидация ответа → `app/regulatory/validators.py` ⭐

```python
def validate_chat_answer(answer, registry, documents=None):
    answer.statements = [_validate_statement(s, registry, report) for s in answer.statements]
    answer.answer_markdown = _strip_unknown_inline_refs(answer.answer_markdown, valid_ids, report)
    if documents is not None:
        report.unsupported_act_numbers = check_act_numbers(answer.answer_markdown, registry, documents)
```

Три проверки:
1. номера цитат, которых нет в реестре, **удаляются** из текста и из тезисов;
2. упоминания актов в тексте («Решение № 85») сверяются со списком номеров
   документов корпуса — регуляркой `_ACT_REFERENCE_RE`;
3. если реестр пуст — ответ принудительно помечается как необоснованный.

Всё удалённое показывается пользователю в блоке «Как получен этот ответ».

### Шаг 10. Расчёт уверенности → `app/regulatory/reasoning.py` ⭐

Считается **кодом**, по наблюдаемым признакам, с объяснением каждого вклада:

```python
score += weights.has_any_source                    # +0.20 нашлись источники
score += weights.has_binding_source                # +0.25 есть обязательные акты ЕАЭС
score += weights.statements_are_cited * share      # +0.20 × доля утверждений со ссылками
score += weights.retrieval_strength * strength     # +0.10 × релевантность лучшего фрагмента
score += weights.version_confirmed * confirmed_share  # +0.10 подтверждённая редакция
score -= weights.conflict_penalty                  # −0.15 расхождения между источниками
score -= weights.superseded_penalty                # −0.15 утратившие силу документы
score -= weights.input_insufficient_penalty        # −0.20 не хватает данных о препарате
```

Порог: `≥0.70 → HIGH`, `≥0.45 → MEDIUM`, иначе `LOW`. Отдельное правило: если
ответ не сослался **ни на один** фрагмент — принудительно LOW, сколько бы
хорошего ни нашёл поиск.

### Шаг 11. Отрисовка → `app/ui/components.py`

Порядок вывода: ответ → уточняющие вопросы (если нужны) → строка уверенности →
свёрнутый блок «Как получен этот ответ» → источники с дословными фрагментами.

Функция `normalize_answer_markdown()` склеивает построчный вывод модели в
нормальные абзацы — иначе Streamlit показывает «лесенку» из обрывков.

## 7. Мини-словарь

| Термин | Простыми словами |
|---|---|
| **RAG** | сначала найти документы, потом отвечать по ним, а не по памяти модели |
| **Эмбеддинг** | текст, превращённый в набор чисел, чтобы сравнивать по смыслу |
| **Чанк (фрагмент)** | кусок документа ~1 600 символов, единица поиска и цитирования |
| **BM25** | классический поиск по словам, без нейросетей |
| **RRF** | способ объединить два списка результатов по позициям, а не по оценкам |
| **Реранкинг** | переупорядочивание найденного под конкретный вопрос |
| **top-k** | сколько результатов берём (40 кандидатов, 12 в итоге) |
| **Qdrant** | база для векторов, у нас работает локально в папке |
| **TIER 1–4** | уровень источника: от обязательного акта ЕАЭС до справочного ICH |
| **Галлюцинация** | выдуманный моделью факт или ссылка |
| **Промпт-инъекция** | попытка спрятать команду для модели внутри документа |
