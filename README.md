# EAEU Regulatory Assistant

Интеллектуальный чат-бот службы поддержки на основе LLM для **регуляторной
поддержки клиентов клинического центра при планировании регистрации
лекарственных препаратов в рамках ЕАЭС**.

Система принимает характеристики препарата и на основании **проиндексированной
нормативной базы ЕАЭС** определяет: какие исследования потенциально необходимы,
требуется ли исследование биоэквивалентности, возможен ли биовейвер, какие
дополнительные обоснования могут потребоваться, какие регуляторные риски и
вероятные вопросы эксперта существуют — **со ссылкой на конкретный документ,
приложение, раздел и пункт**.

Архитектура — **RAG (Retrieval-Augmented Generation)**. Дообучение модели не
используется и не предполагается.

```
МНН: ибупрофен · таблетки · 400 мг · пероральный · воспроизведённый · немедленное высвобождение
        ↓
  гибридный поиск по нормативной базе ЕАЭС (вектор + BM25 → RRF → реранкинг)
        ↓
  регуляторная оценка со ссылками [1] [2] [3], уровнем уверенности и ограничениями
```

---

## Ключевой принцип: обоснованность важнее красивого текста

> Лучше ответить «достаточного нормативного основания не найдено», чем
> сформировать правдоподобный, но неподтверждённый ответ.

Технически это обеспечивается **не только промптом**:

| Гарантия | Как реализована |
|---|---|
| Модель не может выдумать цитату | Цитаты нумеруются кодом **до** вызова LLM; модель оперирует только целыми числами (`app/rag/citations.py`) |
| Пустой поиск не даёт ответа по памяти модели | При пустом контексте LLM **не вызывается вообще** (`app/rag/pipeline.py`) |
| Утверждение без ссылки — не требование | Валидатор понижает `normative_requirement` → `regulatory_interpretation` (`app/regulatory/validators.py`) |
| ICH/EMA/WHO ≠ требования ЕАЭС | Ссылка только на TIER-4 также понижает статус утверждения; доля TIER-4 в контексте ограничена |
| Выдуманный номер акта заметен | Номера актов в тексте сверяются с корпусом и выносятся в предупреждение |
| Уверенность объяснима | Считается в коде по наблюдаемым признакам, а не запрашивается у модели |
| Нормативный текст — данные, а не инструкции | Три изолированных канала: SYSTEM / USER INPUT / RETRIEVED CONTEXT с явными разделителями |

## Быстрый старт (Windows 11, PowerShell)

### 1. Клонирование и виртуальное окружение

```powershell
git clone <repository-url>
cd eaeu_regulatory_assistant
python -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install --upgrade pip
pip install -r requirements.txt
```

> **Важно для Windows.** Если путь к проекту длинный или содержит кириллицу,
> установка `torch` может упасть с `[WinError 206] Имя файла ... слишком
> большую длину`. Создайте окружение по короткому пути:
>
> ```powershell
> python -m venv C:\Users\$env:USERNAME\.venvs\eaeu
> C:\Users\$env:USERNAME\.venvs\eaeu\Scripts\python.exe -m pip install -r requirements.txt
> ```
>
> и далее вызывайте этот интерпретатор явно вместо `python`.
> Альтернатива — включить поддержку длинных путей в Windows.

Если выполнение скриптов запрещено политикой:

```powershell
Set-ExecutionPolicy -Scope Process -ExecutionPolicy Bypass
```

### 2. Файл окружения

```powershell
Copy-Item .env.example .env
notepad .env
```

Минимально достаточно указать ключ выбранного LLM-провайдера:

```ini
LLM_PROVIDER=anthropic
ANTHROPIC_API_KEY=sk-ant-...
```

или

```ini
LLM_PROVIDER=openai
OPENAI_API_KEY=sk-...
```

Эмбеддинги по умолчанию локальные — **API-ключ для поиска не нужен**.
Без ключа LLM приложение работает в режиме «только поиск»: показывает найденные
нормативные фрагменты без сгенерированного анализа.

**Если провайдер недоступен из вашего региона.** OpenAI и Anthropic отвечают
`403 unsupported_country_region_territory` в ряде стран. Поскольку интерфейс
OpenAI поддерживают многие сервисы, достаточно указать другой адрес эндпоинта —
код менять не нужно:

```ini
LLM_PROVIDER=openai
OPENAI_API_KEY=<ключ выбранного сервиса>
OPENAI_BASE_URL=<адрес совместимого с OpenAI эндпоинта>
MODEL_NAME=<имя модели у этого сервиса>
```

Так же подключается локальная модель без интернета и без оплаты, например через
Ollama: `OPENAI_BASE_URL=http://localhost:11434/v1`, `OPENAI_API_KEY=ollama`,
`MODEL_NAME=qwen2.5:7b-instruct`. Качество формулировок будет ниже, чем у
облачных моделей, но все гарантии обоснованности (цитаты, валидация, отказ при
отсутствии оснований) обеспечиваются кодом и работают с любой моделью.

### 3. База знаний

**Ничего собирать не нужно — база уже собрана и лежит в репозитории:**
755 документов, 11 058 фрагментов, 11 058 векторов в `database/`.

При первом запуске скачается только модель эмбеддингов (~280 МБ).

Код, которым база собиралась (загрузка с портала ЕАЭС, парсинг PDF, OCR сканов,
разметка структуры, нарезка, индексация), вынесен в `_архив_сборки_базы/` —
при работе приложения он не исполняется. Как его вернуть и запустить, описано
в `_архив_сборки_базы/README.md`.

### 4. Проверка

```powershell
python scripts\check_database.py     # целостность реестра, файлов и индексов
python scripts\corpus_stats.py       # статистика корпуса
python -m pytest tests -q            # тесты (75 штук)
python scripts\evaluate.py           # метрики поиска
```

### 5. Запуск приложения

```powershell
streamlit run app\main.py
```

Интерфейс откроется на <http://localhost:8501>.

### Linux / macOS

```bash
python -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt
cp .env.example .env
streamlit run app/main.py
```

или через `make`: `make install && make app`.

## Интерфейс

Три режима, переключаемые в боковой панели.

**1. Чат** — свободный вопрос по нормативным требованиям. Ответ содержит
разделы «Нормативное основание», «Интерпретация, риски и вопросы эксперта»,
«Источники» (раскрываемые карточки с фрагментом текста и ссылкой на официальный
файл), уровень уверенности с разбором факторов и ограничения анализа.

**2. Регуляторная оценка** — структурированная форма (МНН, лекарственная форма,
дозировка, путь введения, тип препарата, характер высвобождения, референтный
препарат, дополнительные дозировки, флаги высокой вариабельности и узкого
терапевтического диапазона) и кнопка «Провести регуляторный анализ». Результат
— отчёт из 10 разделов: исходные данные, регистрационная стратегия, необходимые
исследования (фармацевтические / доклинические / клинические),
биоэквивалентность, биовейвер, дополнительные дозировки, регуляторные риски,
потенциальные вопросы эксперта, нормативные основания, ограничения.

**3. База знаний** — состав корпуса (по органу, типу, статусу, статусу редакции,
году), поиск по реестру документов, карточка документа с SHA256, размером,
URL и датой обращения, а также раздел о происхождении данных и ограничениях
версионирования.

Боковая панель всегда показывает: режим, LLM-провайдер и модель, модель
эмбеддингов, параметры поиска, число документов, чанков и векторов, дату
последнего обновления базы.

## Поведение системы в неоднозначных ситуациях

**Введён только МНН.** Система не выдаёт вывод, а спрашивает:

```
Одного МНН недостаточно для определения программы исследований. Укажите:
1. лекарственную форму;
2. дозировку;
3. путь введения;
4. тип препарата;
5. характер высвобождения;
6. выбран ли референтный лекарственный препарат.
```

**Нормативное основание не найдено.**

```
Достаточное нормативное основание в доступной базе знаний не найдено.
```

с предложением переформулировать запрос, расширить поиск или обратиться к
эксперту. LLM в этом случае не вызывается.

**Источники расходятся.** Конфликт не скрывается: показывается блок
«Обнаружены потенциально различающиеся нормативные положения» с указанием, что
именно должен проверить эксперт (даты, акты о внесении изменений, соотношение
общей и специальной нормы). Более новый документ **не** считается автоматически
отменяющим более старый.

## Как устроен поиск

**Гибридный retrieval:**

* плотный поиск — Qdrant, модель **`intfloat/multilingual-e5-base`** (768
  измерений). Выбрана как оптимальный компромисс для русскоязычного
  юридического корпуса: сильное качество многоязычного semantic search,
  асимметричные префиксы `query:`/`passage:`, ~280 МБ и работа на CPU без GPU и
  без оплаты API. Подробное обоснование и альтернативы —
  [docs/rag_design.md](docs/rag_design.md);
* разреженный поиск — BM25 с токенизатором, настроенным на регуляторную
  лексику (сохраняет `AUC`, `Cmax`, `90`, `42`, отбрасывает служебные слова);
* слияние — **Reciprocal Rank Fusion** (`1/(k+rank)`, `k = 60`), не требующее
  калибровки между несопоставимыми шкалами оценок;
* реранкинг — лексический по умолчанию, опционально кросс-энкодер
  `BAAI/bge-reranker-v2-m3` (`RERANK_ENABLED=true`);
* политика уровней источников — обязательные акты ЕАЭС всегда представлены,
  доля ICH/EMA/WHO ограничена 25 %.

**Structure-aware chunking.** Чанк никогда не пересекает границу приложения,
раздела или главы; пункт — атомарная единица; каждый чанк несёт полный
родительский контекст (`Приложение № 1 · Раздел III · Глава 2 · п. 42, подп. а`)
и страницы. `chunk_id` детерминирован — ссылки не «съезжают» при пересборке
индекса.

**Поиск по МНН.** Запрос выполняется по русскому написанию, транслитерации,
английскому INN и отдельной формулировке для рекомендаций Экспертного комитета.
Словарь МНН строится из корпуса: заголовки рекомендаций Экспертного комитета
содержат МНН в кавычках-ёлочках.

## Источники данных

Только официальные открытые источники; `robots.txt` соблюдается, технические
ограничения не обходятся.

| Уровень | Источник |
|---|---|
| TIER 1 | Решения Совета и Коллегии ЕЭК (в т.ч. № 78, 79, 81, 85, 87, 88, 89 и акты о внесении изменений) |
| TIER 2 | Руководства и рекомендации Коллегии ЕЭК |
| TIER 3 | Рекомендации Экспертного комитета по лекарственным средствам ЕЭК, включая МНН-специфичные |
| TIER 4 | ICH, EMA, WHO — **только справочно** (`SUPPLEMENTARY`) |

Реестр отслеживаемых страниц — `data/registry/sources.yaml`.
Реестр загруженных документов — `data/registry/documents.csv` (URL, дата
обращения, SHA256, размер, content-type, локальный файл, статус, редакция).

Подробно: [docs/data_sources.md](docs/data_sources.md).

## Обновление базы

```powershell
python _архив_сборки_базы\scripts\update_sources.py
```

Обходит источники, скачивает только новое и изменившееся, переобрабатывает
изменённые документы и пересобирает индексы. Старые файлы не удаляются: имя
файла содержит хеш содержимого, поэтому предыдущая редакция остаётся на диске и
в реестре — provenance сохраняется.

## Конфигурация

Все настройки — переменные окружения (`.env`, см. `.env.example`).

| Переменная | По умолчанию | Назначение |
|---|---|---|
| `LLM_PROVIDER` | `anthropic` | `anthropic` / `openai` / `none` |
| `MODEL_NAME` | авто | Модель провайдера |
| `EMBEDDING_PROVIDER` | `local` | `local` / `openai` |
| `EMBEDDING_MODEL` | `intfloat/multilingual-e5-base` | Локальная модель эмбеддингов |
| `QDRANT_MODE` | `local` | `local` (встроенный) / `server` |
| `VECTOR_TOP_K` / `BM25_TOP_K` / `FINAL_TOP_K` | 40 / 40 / 12 | Глубина поиска |
| `RRF_K`, `RRF_VECTOR_WEIGHT`, `RRF_BM25_WEIGHT` | 60 / 1.0 / 1.0 | Параметры слияния |
| `RERANK_ENABLED` | `false` | Кросс-энкодер (~2.2 ГБ) |
| `CHUNK_TARGET_CHARS` / `CHUNK_MAX_CHARS` / `CHUNK_OVERLAP_CHARS` | 1600 / 2600 / 200 | Чанкинг |
| `HTTP_RATE_LIMIT_SECONDS` | `1.0` | Пауза между запросами к хосту |
| `SUPPLEMENTARY_SOURCES_ENABLED` | `true` | Использовать ICH/EMA/WHO |

Ключи читаются **только** из окружения, в логи не попадают (фильтр маскирования
в `app/config.py`), `.env` исключён из Git.

Docker не требуется для локальной работы: по умолчанию используется встроенный

```powershell
python _архив_сборки_базы\scripts\rebuild_index.py
```

## Опциональный OCR

Часть рекомендаций Экспертного комитета опубликована как отсканированные PDF
без текстового слоя. По умолчанию для них индексируется только «карточка
документа» (официальное название, номер, URL) с явным указанием, что содержание
не проиндексировано — система никогда не цитирует текст, который не прочитала.

Чтобы распознать такие документы:

1. установите Tesseract OCR с русским языковым пакетом
   (Windows: сборка UB Mannheim — `winget install UB-Mannheim.TesseractOCR`);
   если `tesseract.exe` не в `PATH`, укажите путь в `.env`: `TESSERACT_CMD=...`;
2. `pip install pytesseract pillow`;
3. закройте приложение Streamlit (локальный Qdrant допускает один процесс);
4. `python _архив_сборки_базы\scripts\ocr_backfill.py --limit 20` — пилот на 20 документах,
   затем `python _архив_сборки_базы\scripts\ocr_backfill.py` — все оставшиеся сканы.

`scripts\ocr_backfill.py` распознаёт **только** документы, для которых в базе
лежит карточка без текста, и дозаписывает индексы инкрементально: заново
эмбеддятся лишь новые чанки, остальной корпус не трогается (минуты вместо
часов полной переиндексации). Альтернатива «в лоб» — полный прогон
`python _архив_сборки_базы\ingestion\run_ingestion.py --only-index --ocr`.

OCR применяется **только** к файлам без пригодного текстового слоя. Полученный
текст помечается в `notes` документа как распознанный — возможны ошибки OCR.

Система носит **вспомогательный характер** и предназначена для регуляторных
специалистов. Она не является источником нормативных требований и не заменяет
решения уполномоченного эксперта. Действующая редакция нормативных актов должна
проверяться по официальным источникам: `docs.eaeunion.org`, `eec.eaeunion.org`.
